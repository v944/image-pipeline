## Сессия: починки оплаты, шаринга и подписок

### Платежи (крипто)
- **QR-код генерируется локально** (пакет `qrcode`, data-URL) вместо стороннего api.qrserver.com — CSP больше не блокирует QR, адрес кошелька не уходит третьей стороне (`CryptoModal.tsx`).
- **Верификация TxID — прямой поиск по хешу**: TronScan `transaction-info`, фолбэк Trongrid `/transactions/{hash}/events` + base58→hex конвертация адреса. Убран лимит «последние 30 транзакций», который терял платежи на активном кошельке (`api/crypto/verify.ts`).
- **Восстановление плана по email**: новый эндпоинт `/api/crypto/recover` (POST — отправляет одноразовую ссылку, GET — валидирует токен и возвращает sessionId); запись `recovery:{email}` создаётся в `/api/crypto/receipt` (в запрос добавлен `sessionId`). UI на `/pricing`: блок «Уже оплатили?» + обработка `?restore=`. Работает для покупок, где email был указан при оплате.
- Мелочь: `upgradeUrl` в `/api/check-limit` исправлен с `/upgrade` (404) на `/pricing`.

### Шаринг пайплайнов
- Кнопка **Share** в шапке редактора — создаёт ссылку `/s/:id` и копирует её в буфер.
- Новый роут `/s/:shareId` и страница `SharePage` — загружает чужой пайплайн в редактор.
- Whitelist типов нод в `share.ts` расширен до всех 19 (было 9 — пайплайны с новыми нодами отклонялись); лимит нод 20 → 100.

### Подписки и рассылка
- `/api/subscribe`: rate limit 5/мин/IP + **double opt-in** (письмо-подтверждение со ссылкой, действует 24 ч). Без `RESEND_API_KEY` — прежнее поведение (single opt-in).
- Новый эндпоинт `/api/unsubscribe` — одноразовая токен-ссылка, удаляет из рассылки. Токен выдаётся при подтверждении подписки.
- `/api/newsletter`: персональные ссылки отписки в каждом письме (CAN-SPAM/GDPR); ключ принимается из заголовка `x-admin-key` (query `?key=` сохранён для совместимости).

### Прочее
- `/api/cleanup`: реальная работа вместо заглушки — чистка маркеров прошлых запусков и протухших abuse-логов (>30 дней), статистика KV.
- `kv.ts`: добавлен `zrem`.
- i18n: новые ключи `pricing.restore*`, `editor.share*`, `share.*` (en + ru); `landing.emailSuccess` теперь про проверку почты.

Проверки: `tsc -b` — 0 ошибок; vitest — 54/54; oxlint — 0 ошибок (7 пре-существующих warning'ов в нетронутых файлах); `npm run build` — ок. Новая зависимость: `qrcode` (+ `@types/qrcode`).

## 1. Нода HSL (объединение Оттенка и Насыщенности)

Отдельные ноды «Оттенок» (Hue) и «Насыщенность» (Saturation) объединены в одну ноду **HSL** с тремя параметрами: Оттенок, Насыщенность, Освещённость (Lightness).

### Было
- Две отдельные ноды: `saturation` (ползунок −100…100) и `hue` (ползунок −180…180).
- Отдельные canvas-функции `applySaturation` / `applyHue`.
- Отдельные превью (`SaturationPreview` + `AdjustmentPreview` для hue).
- Два разных формата данных в сторе: `{ saturation }` и `{ value }`.

### Стало
- Одна нода **`hsl`** с данными `{ hue: 0, saturation: 0, lightness: 0 }`.
- Единая canvas-функция `applyHsl` (`src/core/canvas/hsl.ts`), обрабатывает все три канала в одном проходе (базируется на общих `rgbToHsl`/`hslToRgb` из `color.ts`).
- Старые файлы `saturation.ts`, `hue.ts`, `SaturationPreview.tsx` удалены.
- Тип ноды `saturation`/`hue` заменён на `hsl` (types, store, preview-utils, PipelineEngine, BaseNode).
- i18n: `nodePalette.hsl`, `settings.hsl.{hue,saturation,lightness}` (en + ru).
- Палитра: в группе Adjust появляется нода «HSL» с бейджем NEW.

## 2. Единое большое окно просмотра (как у Blur)

Все корректирующие/фильтрующие ноды переведены на единый формат превью — **одно большое окно** (`w-full`) с Zoom-лупой 100%, как у ноды Blur.

### Было
- Двухпанельное превью «Оригинал → Откорректировано» (две мини-картинки `aspect-[4/3]`) и модалка сравнения (`CompareModal`) у:
  - Brightness, Contrast, Exposure, Temperature (`AdjustmentPreview`)
  - Emotion (`EmotionPreview`)
  - Saturation / Hue (двухпанельные)

### Стало
- Один большой предпросмотр результата (`PreviewImage` с `w-full` и лупой 100%) у:
  - Brightness, Contrast, Exposure, Temperature (`AdjustmentPreview` переписан)
  - Emotion (`EmotionPreview` переписан, превью-галочка сохранена)
  - HSL (`HslPreview`), Rotate (`RotatePreview`), Denoise (`DenoiseFilterPreview`), Blur/Sharpen/Grayscale (`FilterPreview`)
- Мёртвый код удалён: `CompareModal.tsx`, старый неиспользуемый `DenoisePreview.tsx`.

## 3. Кнопка «Очистить канвас»

В шапке рядом с undo/redo и переключателем языка появилась текстовая кнопка очистки канваса.

### Было
- Отдельной кнопки очистки не было (существующий метод `resetPipeline` в сторе UI не был).
- Существующая кнопка «Очистить всё» чистила только список файлов во вкладке «Файлы».

### Стало
- Текстовая кнопка **«Очистить канвас»** в `Header.tsx`: порядок — Откат назад → Откат вперёд → язык → **отступ** → «Очистить канвас».
- Не иконка мусорки (защита от случайного нажатия), красная окантовка, неактивна при пустом канвасе.
- Подтверждение (`window.confirm`): «Очистить холст? Будут удалены все ноды и соединения. Загруженные файлы останутся.»
- Очищается только канвас (nodes + edges); загруженные файлы во вкладке «Файлы» не удаляются. Операция undo-безопасна (создаёт снимок в history).

## 4. Санитизация нод при загрузке

Автоматическая очистка старых/неизвестных нод при восстановлении схемы.

### Было
- При загрузке из localStorage и старых сохранённых пайплайнов могли оставаться устаревшие ноды (`saturation`, `hue`) и «висячие» соединения.

### Стало
- Экспортирован список `VALID_NODE_TYPES`; в `pipeline.store.ts` добавлена санитизация (`sanitizeLoadedNodes` / `sanitizeLoadedEdges`), применяется:
  - при гидрации из localStorage (`onRehydrateStorage`) — старые ноды удаляются, состояние пересохраняется;
  - при `loadPipeline` (загрузка сохранённых пайплайнов);
- Устаревшие типы и грани, ссылающиеся на удалённые ноды, отсекаются; схема чистится сама.
